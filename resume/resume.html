How I Engineer

  • Spec-driven: non-trivial work starts as an OpenSpec change (propose → review → apply) so intent is reviewed and agreed before any implementation, cutting rework and scope drift.
  • Test-first: I write the failing test, prove it red and explain why, then implement — which keeps regressions out of a large codebase with no green baseline.
  • AI-augmented, standards-held: I use coding agents and curated skills to raise delivery speed while enforcing consistent coding standards and review discipline, not to skip them.
  • Blast-radius discipline: I name which environment and which database a change touches before running it — essential in a system that debits real cards.
  • Security by default: close IDORs, replace permanent asset URLs with short-lived signed ones, and scope sensitive file access to authorized participants.
